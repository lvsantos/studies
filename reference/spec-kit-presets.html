Presets

Presets alteram templates e comandos existentes. Eles adaptam o processo sem acrescentar, por si só, uma nova capacidade ao CLI.

Escolha o bloco

BlocoUse quando
PresetQuer mudar formato, terminologia ou instruções de um processo existente.
ExtensãoPrecisa de novo comando, integração, hook ou fase.
OverrideA mudança é pontual e exclusiva deste projeto.

Resolução de arquivos

1. .specify/templates/overrides/       maior precedência
2. Presets instalados (menor número de prioridade primeiro)
3. Extensões instaladas (prioridade menor primeiro)
4. .specify/templates/                 núcleo

A resolução é independente para cada arquivo. Overrides locais são indicados para ajustes pontuais de template em um projeto; use um preset quando a convenção precisar ser reutilizada. A estratégia padrão é replace, na qual o primeiro arquivo encontrado substitui completamente as versões inferiores. Verifique um nome com specify preset resolve <nome>.

Templates e scripts são consultados na pilha quando necessários. Comandos usam a pilha para substituição/composição, mas são materializados no diretório da integração ativa; o agente não re-resolve a pilha a cada invocação. Instalação e remoção reconciliam comandos afetados.

Estratégias de composição

EstratégiaTemplates/comandosScripts
replaceSubstitui o conteúdo inferior (padrão).Substitui.
prependAdiciona antes do conteúdo inferior.Não suportada.
appendAdiciona depois do conteúdo inferior.Não suportada.
wrapUsa {CORE_TEMPLATE} como ponto de inserção em templates e comandos.Usa $CORE_SCRIPT.

Comandos de ciclo de vida

specify preset search [query]
specify preset info <preset-id>
specify preset add <preset-id>
specify preset list
specify preset resolve <nome-do-arquivo>
specify preset set-priority <preset-id> <N>
specify preset disable <preset-id>
specify preset enable <preset-id>
specify preset remove <preset-id>

Esses comandos exigem um projeto já inicializado com specify init. disable pausa a participação do preset na resolução, mas mantém a instalação; remove desinstala e limpa os comandos registrados. Revise a origem e os arquivos antes de instalar componentes da comunidade.

Regra prática

Regra compartilhada entre projetos → preset. Ajuste de um projeto → override local. Comportamento novo ou integração externa → extensão.

Criar um preset próprio

  1. Defina a convenção compartilhada e o resultado observável.
  2. Escolha template (estrutura do documento), command (instruções do agente) ou extensão (capacidade/integração nova).
  3. Copie presets/scaffold, personalize o ID e metadados do preset.yml, remova exemplos irrelevantes e escreva só os arquivos necessários.
  4. Prefira append para acrescentar conteúdo sem substituir o template central; use replace quando pretende ser dono do arquivo inteiro.
  5. Em projeto de laboratório com specify init, instale com specify preset add --dev ./meu-preset, confira specify preset resolve plan-template, gere um artefato real e depois remova o preset.
  6. Para compartilhar: README específico, licença, versão SemVer, arquivos revisados e instruções do guia de publicação.
