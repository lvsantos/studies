Dois caminhos

Feature de produção
constitution → specify → clarify → plan → checklist → tasks → analyze → implement → converge.

Git: benefícios da extensão

A extensão de Git é opcional e pode criar branches numerados para features. Seu valor principal é organizacional:

  • isola cada feature do trabalho principal;
  • facilita revisar spec, plan, tasks e código juntos em um pull request;
  • cria uma trilha de commits entre intenção, decisão e implementação;
  • torna comparação, pausa e reversão menos arriscadas.

Atenção: a feature ativa é resolvida pelo estado em .specify/feature.json (ou pela variável de ambiente correspondente), não apenas pelo branch atual. Git organiza a mudança; o estado do Spec Kit diz qual pasta os comandos devem usar.

Formas equivalentes

Este projeto usa skills do Copilot, por isso os comandos aparecem com hífens: /speckit-specify. A documentação oficial também mostra a forma com pontos, /speckit.specify. O nome visual depende do agente; a etapa é a mesma.
