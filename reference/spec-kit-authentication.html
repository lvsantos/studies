Autenticação HTTP

Credenciais opcionais do Specify CLI para acessar fontes remotas protegidas.

Use para

  • Buscar catálogos autenticados;
  • baixar extensões privadas;
  • consultar ou baixar releases protegidas.

Sem configuração, as requisições são anônimas. Isto não configura o Copilot, a integração do agente, Git ou autenticação da aplicação.

Configuração

Crie ~/.specify/auth.json. Exemplo GitHub com token fornecido por variável de ambiente:

{
  "providers": [
    {
      "hosts": ["github.com", "api.github.com", "raw.githubusercontent.com", "codeload.github.com"],
      "provider": "github",
      "auth": "bearer",
      "token_env": "GH_TOKEN"
    }
  ]
}
chmod 600 ~/.specify/auth.json

Guarde o token num gerenciador de segredos ou variável de ambiente segura; evite incluí-lo no JSON, no repositório ou em logs. Conceda apenas as permissões necessárias.

Provedores e esquemas

ProvedorEsquemas documentadosExemplos de uso
GitHubbearerPAT, fine-grained PAT, OAuth ou token de GitHub App.
Azure DevOpsbasic-pat, bearer, azure-cli, azure-adPAT, token OAuth, sessão do Azure CLI ou service principal.
Bitbucketbearer, basicAccess token ou API token; o host e o formato dependem do tipo de token.

Diagnóstico rápido

  • 401/403: confira host, variável de ambiente, validade e permissões de leitura do token.
  • Download falha em outro host: inclua os hosts de origem usados pelo catálogo; a autenticação não é encaminhada para destinos fora da lista declarada.
  • Recurso público funciona sem configuração: comportamento esperado; a autenticação é opt-in.

Entradas podem declarar múltiplos hosts. Os nomes correspondem exatamente ou por wildcard de subdomínio iniciado por *.; esse wildcard não inclui o domínio base.
