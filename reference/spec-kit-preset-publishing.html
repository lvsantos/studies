Publicar presets

O repositório do autor hospeda o pacote. O catálogo comunitário aponta para ele para facilitar a descoberta.

Do diretório à release

  1. Prepare preset.yml, README específico, LICENSE e, de preferência, CHANGELOG.md.
  2. Revise ID (minúsculas e hífens), SemVer, requisito do Spec Kit, dependências e caminhos em provides.
  3. Teste em projeto descartável iniciado com specify init: specify preset add --dev ./meu-preset, specify preset resolve <arquivo>, gere um artefato e remova com specify preset remove <id>.
  4. Atualize versão e changelog; crie uma tag como v1.0.0 e envie ao seu repositório.
  5. Instale pelo arquivo publicado, para testar o pacote que outras pessoas vão receber: specify preset add --from https://github.com/ORG/REPO/archive/refs/tags/v1.0.0.zip.

README que serve ao usuário

Explique o que o preset fornece, quando usar (e quando não usar), requisitos e limitações. A documentação no catálogo deve apontar para um README GitHub alcançável cujo URL termina em README.md. Inclua nele um comando válido specify preset add ...; prefira o mesmo --from usado em download_url.

Submissão comunitária

  1. Faça fork de github/spec-kit e crie uma branch.
  2. Inclua a entrada em presets/catalog.community.json, ordenada por ID.
  3. Inclua a linha em docs/community/presets.md, ordenada pelo nome exibido.
  4. Confira versão, URL de download, URL de documentação, licença, requisitos, contagens de arquivos e tags.
  5. Abra o PR, preencha a checklist vigente e responda à validação/revisão dos mantenedores.
O que cada canal significa

Seu repositório + release: origem pública e instalação direta. Catálogo comunitário: descoberta; o preset continua hospedado por você. A listagem não substitui revisão do código por quem instala e não é endosso de segurança.

Atualizar uma versão existente

Altere a versão em preset.yml, registre a mudança no changelog, publique uma nova tag, teste seu ZIP e abra PR para atualizar version e download_url no catálogo. Não reutilize tags para conteúdo diferente.
