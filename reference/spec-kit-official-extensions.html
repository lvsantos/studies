As quatro extensões oficiais do Spec Kit

Um mapa para escolher entre avaliar uma ideia, corrigir um bug, sincronizar o contexto do agente e organizar o trabalho no Git.

ExtensãoPerguntaArtefato ou efeito
assessA ideia merece investimento?intake, research, define, shape e decision
bugO que quebrou e como provar a correção?assessment, fix e test
agent-contextQue contexto o agente deve carregar?seção sincronizada no arquivo do agente
gitComo organizar o trabalho no versionamento?branches, remotes, validação e commits

Escolha pelo problema

  1. Ideia ainda incerta? Use assess.
  2. Comportamento quebrado? Use bug.
  3. Instruções e plano precisam acompanhar o agente? Use agent-context.
  4. Branches e checkpoints precisam de convenção? Use git.

Instalação e controle

specify extension add assess
specify extension add bug
specify extension add agent-context
specify extension add git

specify extension list
specify extension disable agent-context
specify extension enable git

As quatro são oficiais, bundled e opt-in: estão disponíveis no Spec Kit, mas não são instaladas automaticamente só por inicializar um projeto. Cada uma pode ser instalada ou desativada separadamente.

Uma distinção importante

assess e bug organizam o conteúdo do trabalho. agent-context e git sustentam a execução: uma mantém o agente informado; a outra mantém o trabalho organizado no versionamento.

A extensão git não torna a branch a fonte única da feature ativa. O Spec Kit continua usando o estado em .specify/feature.json ou SPECIFY_FEATURE_DIRECTORY.
