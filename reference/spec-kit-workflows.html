Workflows

Workflows encadeiam comandos, prompts, shell e revisões humanas em execuções rastreáveis e retomáveis.

Escolha a peça

Preciso...Use
Ordenar etapas, condicionar rotas, pausar ou retomarWorkflow
Adicionar comando, capacidade ou integração externaExtension
Mudar instruções ou formato de um processo existentePreset
Fazer ajuste pontual de template neste projetoOverride local

Modelo mental

inputs + requisitos
        ↓
lista ordenada de passos
        ↓
comando / prompt / shell / gate / controle de fluxo
        ↓
estado por execução → status, pausa ou retomada

Expressões como {{ inputs.spec }} passam valores entre entradas e passos. Um gate pode pausar para aprovação; condições e loops podem controlar a próxima ação. Estado em .specify/workflows/runs/<run_id>/.

Comandos de uso

specify workflow search [query]
specify workflow info <id>
specify workflow add <id>
specify workflow list
specify workflow run <id> --input chave=valor
specify workflow status [<run_id>]
specify workflow resume <run_id>
specify workflow disable <id>
specify workflow enable <id>
specify workflow remove <id>

Para experimentar YAML local: specify workflow run ./workflow.yml --input chave=valor. A execução de um arquivo local é a exceção que pode rodar fora de um projeto inicializado; outros comandos normalmente exigem specify init.

Criar e publicar

  1. Desenhe entradas, steps, gates e pré-requisitos; mantenha IDs únicos e expressões apontando para dados disponíveis.
  2. Teste com specify workflow info ./workflow.yml e execute num projeto de laboratório, inclusive pausas e retomadas.
  3. Hospede workflow.yml, README e licença num repositório; publique uma tag SemVer e use a URL raw versionada para instalação direta com specify workflow add <id> --from <url>.
  4. Para descoberta comunitária, abra PR atualizando workflows/catalog.community.json no repositório github/spec-kit; ordene por ID e mantenha versão/URL alinhadas à release.

O catálogo comunitário é discovery-only por padrão. A revisão verifica forma e completude, não é auditoria de segurança; leia steps shell antes de instalar.

Workflows oficiais para reconhecer

  • speckit: specify → revisão → plan → revisão → tasks → implement.
  • bugfix: assess do bug → gate de revisão → fix → test; usa comandos da extensão bug.
  • assess: intake → research → define → shape → decide → gate do veredito; usa comandos da extensão assess.

Cuidados

  • Revise workflows antes de instalar ou executar, especialmente os de terceiros.
  • Passos shell rodam com os privilégios locais; não há sandbox.
  • Interpolação em run não recebe escape automático. Não passe valores não confiáveis ao shell; restrinja entradas sempre que possível.
  • Um gate é um ponto de decisão humana, não uma revisão automática do próximo comando.
