Atualizar sem perder o mapa

CLI, arquivos do projeto e componentes customizados têm ciclos de atualização separados.

Sequência-base

# Fora ou dentro do projeto: confira e atualize a CLI
specify self check
specify self upgrade --dry-run
specify self upgrade

# Dentro do projeto: atualize arquivos da integração
specify integration status
specify integration upgrade <key>

# Atualize componentes pelo respectivo dono
specify extension update
specify preset update <preset-id>
specify workflow update [workflow-id]
specify bundle update [bundle-id]

Use specify self upgrade --tag vX.Y.Z para selecionar uma release. Faça commit/backup antes; confira release notes e diff. A rota normal para arquivos do projeto usa manifestos. Reserve specify init --here --force para recuperação: ela é mais ampla e não faz as mesmas verificações por arquivo.

Quem é dono da atualização?

ArtefatoComandoVerificação
CLIself upgradeself check
Comandos da integração, scripts/templates centraisintegration upgrade <key>integration status e diff
Extensão independenteextension update [id]extension list; teste comandos e hooks
Preset independentepreset update <preset-id>preset resolve <arquivo>; inspecione o comando materializado
Workflow independenteworkflow update [workflow-id]workflow resolve <id>; valide anchors e execute um teste
Bundle instaladobundle update [bundle-id]bundle info <id> e teste os componentes atualizados

Se um componente pertence a um bundle, prefira atualizar pelo bundle para reaplicar os pins do manifesto. Atualização de CLI não atualiza automaticamente presets, workflows, bundles nem extensões independentes. Extensões empacotadas podem exigir a CLI mais nova.

Preset que acrescenta instrução a comando

comando efetivo = comando-base-atual + texto do preset (append)
  1. Atualize a CLI.
  2. Atualize os arquivos da integração.
  3. Revise o preset contra o novo contrato do comando.
  4. Atualize/reconcilie o preset, e confira o arquivo materializado na integração ativa.
  5. Teste o comando e o artefato produzido.

O trecho append tende a continuar junto ao novo texto-base após a recomposição, mas pode ficar obsoleto ou contraditório. replace mascara a implementação do núcleo; wrap depende de seu placeholder. A atualização de preset remove e instala novamente: se a instalação nova falhar, a anterior pode já ter sido removida. Mantenha backup/commit e confira a origem primeiro.

Falhas plausíveis

  • Arquivo da integração modificado: atualização por manifesto pode bloquear. Revise o diff; não passe --force às cegas.
  • Template/override antigo: continua prevalecendo e pode ocultar a atualização do núcleo.
  • Overlay de workflow: pode falhar ao resolver se o workflow-base removeu/renomeou o step ID alvo.
  • Versão principal ou terceiro componente: contrato, requisitos ou esquema podem mudar. A compatibilidade dentro da mesma versão principal não é garantia para todas as extensões e customizações.
  • Comando duplicado no agente: confira pastas atuais e legadas e reinicie o agente/editor.
