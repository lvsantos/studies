Bundles

Unidades versionadas para provisionar um conjunto de componentes por papel ou equipe.

Modelo mental

bundle.yml
  ├── extensões: novas capacidades
  ├── presets: instruções e formatos
  ├── steps: etapas reutilizáveis
  └── workflows: processos ordenados

bundle = distribuição/composição
         dos componentes declarados

Bundle não adiciona comportamento de execução próprio: cada extensão, preset, step ou workflow continua sendo instalado pelo mecanismo correspondente.

Escolha a peça

NecessidadeUse
Adicionar comando, integração ou capacidadeExtension
Adaptar instrução ou formato existentePreset
Ordenar etapas e gates de um processoWorkflow
Distribuir o setup completo de um papel/equipeBundle

Comandos principais

specify bundle search [query]
specify bundle info <bundle_id>
specify bundle install <bundle_id | path>
specify bundle list
specify bundle update [<bundle_id> | --all]
specify bundle remove <bundle_id>
specify bundle init [<bundle_id>]
specify bundle validate [--path <dir-ou-manifesto>]
specify bundle build [--path <dir>] [--output <dir>]

add é alias de install. search e info funcionam fora de projeto; install/init podem inicializar um projeto. O manifesto local declara dependências, mas os payloads dos componentes ainda são resolvidos pelos catálogos ativos.

Inspeção e governança

  • Use info para ver o conjunto expandido, versões fixadas, prioridades/estratégias de preset e indicador de confiança antes de instalar.
  • Bundles first-party do catálogo oficial são curados e marcados verified; bundles comunitários são descoberta por padrão e não equivalem a auditoria.
  • Revise a origem do bundle e também os catálogos de extensions, presets, workflows e steps que fornecem seus componentes.
  • Uma integração fixada deve corresponder à integração ativa do projeto; instalação não deve ser tratada como troca de integração.
  • Remoção limpa os componentes fornecidos pelo bundle, exceto os ainda necessários por outro bundle. Componentes independentes não são adotados.
  • Atualizações re-resolvem componentes; versões fixadas são aplicadas quando instalados ou atualizados/refrescados.
  • Instalação totalmente offline tem limites: bundles de catálogo e componentes não empacotados no Spec Kit podem precisar de rede.

Bundles first-party

  • bugfix: extension bug@1.0.0 + workflow bugfix@1.0.0; requer Spec Kit >=0.9.0.
  • assess: extension assess@1.0.1 + workflow assess@1.0.0; requer Spec Kit >=0.9.0.

São os dois IDs first-party do catálogo padrão, marcados verified. bundle info mostra o plano expandido. O workflow não é substituído pelo bundle: ele continua chamando os comandos fornecidos pela extension correspondente.

Manifests de exemplo (não são bundles first-party)

Os diretórios em examples/bundles demonstram composição por papel; não fazem parte do catálogo first-party e não são instaláveis por ID apenas por existirem no repositório. Os manifests precisam ter todas as dependências resolvidas por componentes incluídos, já instalados ou catálogos ativos:

ExemploComposição declarada
business-analystagent-context, preset de elicitação, 2 steps e workflow de requisitos para spec.
developeragent-context, preset de planejamento, 2 steps e workflow de spec para implementação.
product-manageragent-context, preset de discovery, 2 steps e workflow de spec para roadmap.
security-researcheragent-context, preset de compliance (priority 5), 2 steps e workflow secure SDD.
 
specify bundle validate --path examples/bundles/developer
specify bundle build --path examples/bundles/developer --output dist/

Use-os para aprender/autorar manifests; confirme no catálogo e nas origens configuradas se cada ID referenciado existe antes de tentar instalar o ZIP gerado.

Bundles comunitarios

O catalogo comunitario embutido e discovery-only: search e info funcionam, mas instalar pelo ID exige uma origem explicitamente install-allowed. Isso e uma politica de origem, nao uma verificacao de seguranca.

Consulta de 2026-10-03: agentstandards (1 extension, 1 preset, 1 workflow), sicario-spec (1 extension, 11 presets) e specassay (1 extension, 1 preset). Todos aparecem como nao verificados. O catalogo valida metadados; nao audita nem endossa os componentes.

specify bundle search security
specify bundle info sicario-spec
specify bundle catalog list
# Instale um ZIP revisado ou use um catalogo curado com install-allowed
specify bundle install ./sicario-spec-reviewed.zip

Mesmo instalando um manifesto/ZIP local, extensions, presets, workflows e steps que nao estejam incluidos ou instalados ainda precisam resolver nos catalogos ativos correspondentes. Revise tambem essas origens.
