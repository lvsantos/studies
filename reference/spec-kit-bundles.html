Bundles

Unidades versionadas para provisionar um conjunto de componentes por papel ou equipe.

Modelo mental

bundle.yml
  ├── extensões: novas capacidades
  ├── presets: instruções e formatos
  ├── steps: etapas reutilizáveis
  └── workflows: processos ordenados

bundle = distribuição/composição
         dos componentes declarados

Bundle não adiciona comportamento de execução próprio: cada extensão, preset, step ou workflow continua sendo instalado pelo mecanismo correspondente.

Escolha a peça

NecessidadeUse
Adicionar comando, integração ou capacidadeExtension
Adaptar instrução ou formato existentePreset
Ordenar etapas e gates de um processoWorkflow
Distribuir o setup completo de um papel/equipeBundle

Comandos principais

specify bundle search [query]
specify bundle info <bundle_id>
specify bundle install <bundle_id | path>
specify bundle list
specify bundle update [<bundle_id> | --all]
specify bundle remove <bundle_id>
specify bundle init [<bundle_id>]
specify bundle validate [--path <dir-ou-manifesto>]
specify bundle build [--path <dir>] [--output <dir>]

add é alias de install. search e info funcionam fora de projeto; install/init podem inicializar um projeto. O manifesto local declara dependências, mas os payloads dos componentes ainda são resolvidos pelos catálogos ativos.

Inspeção e governança

  • Use info para ver o conjunto expandido, versões fixadas, prioridades/estratégias de preset e indicador de confiança antes de instalar.
  • Bundles first-party do catálogo oficial são curados e marcados verified; bundles comunitários são descoberta por padrão e não equivalem a auditoria.
  • Revise a origem do bundle e também os catálogos de extensions, presets, workflows e steps que fornecem seus componentes.
  • Uma integração fixada deve corresponder à integração ativa do projeto; instalação não deve ser tratada como troca de integração.
  • Remoção limpa os componentes fornecidos pelo bundle, exceto os ainda necessários por outro bundle. Componentes independentes não são adotados.
  • Atualizações re-resolvem componentes; versões fixadas são aplicadas quando instalados ou atualizados/refrescados.
  • Instalação totalmente offline tem limites: bundles de catálogo e componentes não empacotados no Spec Kit podem precisar de rede.

Exemplos oficiais

  • bugfix: extensão bug + workflow bugfix.
  • assess: extensão assess + workflow assess.
  • business-analyst (exemplo): contexto do agente + preset + steps + workflow.
