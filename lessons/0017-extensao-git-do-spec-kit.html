Git Branching Workflow: organizar o trabalho em branches

Vitória de hoje: entender como a extensão oficial git organiza branches, remotes e commits sem confundir controle de versão com o estado da feature que o Spec Kit está usando.

O mapa mental

Bug Fix organiza diagnóstico, correção e prova. Idea Assessment organiza pesquisa e decisão. Git Branching Workflow organiza a camada de versionamento que envolve esses trabalhos.

Ela é uma extensão oficial, bundled e opt-in. O fluxo principal do Spec Kit continua funcionando sem Git; a extensão acrescenta convenções e automações para equipes que querem esse controle.

1. Que problema ela resolve?

Sem uma convenção, diferentes pessoas podem criar branches com nomes incompatíveis, esquecer de detectar o remote ou commitar artefatos em momentos diferentes. Isso torna mais difícil revisar o resultado de uma especificação, de um bug fix ou de uma decisão de produto.

A extensão concentra operações Git relacionadas ao workflow: inicializar o repositório, criar branch de feature, validar o nome, detectar o remote e, se configurado, fazer commits automáticos.

2. Como instalar

specify extension add git

Para desativar sem remover:

specify extension disable git
# Para reativar:
specify extension enable git

Se Git não estiver instalado ou o diretório não for um repositório, a extensão degrada com avisos: os diretórios de especificação continuam sendo criados, mas branches, validação e detecção de remote são ignorados.

3. Comandos disponíveis

Comando canônicoFunção
speckit.git.initializeInicializa o repositório com uma mensagem configurável.
speckit.git.featureCria uma branch numerada para uma feature.
speckit.git.validateVerifica se a branch segue a convenção.
speckit.git.remoteDetecta a URL do remote para integrações GitHub.
speckit.git.commitFaz commit automático quando habilitado.

Em uma integração com skills baseadas em hífen, por exemplo, speckit.git.feature é invocado como:

/speckit-git-feature

O comando pode criar nomes como 001-offline-mode. A numeração pode ser sequencial ou baseada em timestamp.

4. Hooks e configuração

A configuração fica em:

.specify/extensions/git/git-config.yml

Você pode configurar a estratégia de numeração, um template de branch e o estilo das mensagens de commit. Os commits automáticos ficam desativados por padrão e podem ser habilitados por etapa, como depois de specify, plan, tasks ou implement.

Isso é importante: instalar a extensão não significa autorizar commits automáticos. A equipe precisa escolher explicitamente quais hooks serão habilitados.

5. Um detalhe que evita confusão

O quickstart atual diferencia branch Git de feature ativa. O Spec Kit resolve os comandos pelo estado registrado em .specify/feature.json, ou pela variável SPECIFY_FEATURE_DIRECTORY. Portanto, trocar de branch com git checkout não muda sozinho a feature ativa para os comandos do Spec Kit.

A extensão Git ajuda a nomear e organizar branches, mas não transforma a branch em fonte única da verdade do estado da feature. Essa separação evita executar comandos contra o diretório errado.

6. Como ela se relaciona com Bug Fix e Assess?

  • Depois de um Idea Assessment com resultado go, use a extensão Git para criar e validar a branch que carregará a feature.
  • Durante um Bug Fix, use a extensão Git para manter a correção isolada e registrar checkpoints, se os hooks estiverem configurados.
  • Nem git nem agent-context decidem se uma ideia vale a pena ou qual é a causa de um bug. Eles sustentam a execução desses processos.

7. Quando usar

  • a equipe precisa de nomes de branch previsíveis;
  • o fluxo depende de um remote GitHub detectável;
  • commits por etapa ajudam a revisar ou recuperar o trabalho;
  • o projeto quer adotar uma política Git sem duplicar scripts em cada feature.

Se o projeto ainda não usa Git ou se a equipe já tem um workflow consolidado, mantenha a extensão desativada até que a automação realmente reduza trabalho.

8. Prática: qual extensão escolher?

Um bug foi avaliado, corrigido e testado. O time agora quer que cada etapa gere um checkpoint com mensagem consistente, sem alterar o diagnóstico nem a validação do bug. Qual extensão atua nessa necessidade?

Use git. A extensão Bug Fix continua responsável por assess, fix e test; a extensão Git cuida dos commits e da organização do trabalho em versionamento.
