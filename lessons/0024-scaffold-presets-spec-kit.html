Scaffold: transforme uma convenção em preset próprio

Vitória de hoje: usar o scaffold oficial como ponto de partida para empacotar templates e instruções repetíveis sem confundir o molde de desenvolvimento com um preset pronto para instalar.

Uma distinção que evita uma busca inútil

presets/scaffold é um diretório-modelo do repositório oficial. Ele não é um preset publicado cujo ID seja scaffold: o preset.yml começa com ID my-preset e metadados de exemplo. A finalidade é copiar, editar e testar um preset seu.

Isso resolve o problema de começar do zero sem inventar o formato do manifest, a estrutura de arquivos e os passos básicos de teste.

1. O que vem no molde

O scaffold demonstra templates de documentos e comandos de agente. O README inclui exemplos como spec-template, speckit.specify e um template/comando ilustrativo para uma extensão chamada myext; esses nomes de exemplo não significam que sua equipe tenha essa extensão instalada.

O preset.yml ensina a declarar o tipo de cada item, o nome usado para resolução, o caminho do arquivo, uma descrição e, opcionalmente, o item que ele substitui e a estratégia de composição. Os campos essenciais identificam o preset (ID, nome, versão, descrição), a versão mínima do Spec Kit e a lista de arquivos fornecidos.

2. Fluxo de criação e teste

Partindo de uma cópia local do repositório oficial, copie o diretório de exemplo, ajuste o manifest e remova os exemplos que não atendem à sua convenção:

cp -r presets/scaffold my-preset
# Edite my-preset/preset.yml e os arquivos de templates/ e commands/
specify preset add --dev ./my-preset
specify preset resolve spec-template
specify preset remove my-preset

Antes de instalar, altere o campo preset.id e complete nome, versão, descrição, autor, repositório, compatibilidade e conteúdo. O identificador passado ao remover precisa ser o ID declarado no manifest, não necessariamente o nome do diretório.

  1. Escreva uma regra concreta e reutilizável que a equipe quer compartilhar entre projetos.
  2. Escolha se ela muda a estrutura do artefato (template) ou como o agente trabalha (command).
  3. Declare o arquivo e a estratégia no manifest.
  4. Instale com --dev num projeto de teste; verifique os nomes com specify preset resolve.
  5. Gere um artefato real e confirme que a regra está presente e que o comando central não perdeu comportamento necessário.

3. Escolher a estratégia de composição

EstratégiaResultadoExemplo
replaceSubstitui o arquivo de menor prioridade inteiro.Reformular o template da spec.
prependAcrescenta orientação antes do conteúdo de menor prioridade.Exigir que o agente leia uma regra antes do comando central.
appendAcrescenta conteúdo depois do arquivo base.Adicionar uma seção de conformidade a um template.
wrapInsere o conteúdo inferior em {CORE_TEMPLATE}.Manter o comando central e cercá-lo com uma checagem própria.

Para scripts, apenas replace e wrap são suportadas; wrappers de script usam $CORE_SCRIPT. Prefira a composição quando a regra é um complemento e você quer receber melhorias futuras do core. Use replace apenas quando pretende ser dono do comportamento completo.

4. O que testar antes de compartilhar

O comando --dev instala uma cópia local do pacote para experimentação; ele não publica o preset para colegas nem o inclui automaticamente no catálogo da equipe. Antes de distribuir, valide o manifest, documente os conflitos e faça o processo de publicação oficial ou disponibilize um catálogo confiável.

  • Um template ausente continua sendo resolvido por outra camada da pilha.
  • Se outro preset fornecer o mesmo arquivo, a prioridade e a estratégia produzem o resultado esperado.
  • O comando continua compatível com a integração de agente em uso.
  • O preset não promete capacidade nova de CLI: se o caso exige uma etapa executável ou integração, avalie uma extensão.

5. Pratique: pode instalar pelo nome?

Você quer experimentar o diretório oficial presets/scaffold. Qual ID deve usar para instalá-lo diretamente, sem editar nada?

Nenhum ID pronto: copie e personalize primeiro. O manifest de exemplo declara my-preset; altere os metadados e teste a sua cópia com specify preset add --dev ./my-preset.
