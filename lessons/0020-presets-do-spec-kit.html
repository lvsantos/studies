Presets: mudar o processo sem mudar o motor

Vitória de hoje: prever qual template ou comando será usado e escolher entre preset, override e extensão para uma necessidade real.

A ideia central

Um preset adapta o comportamento que o Spec Kit já tem: pode trocar a estrutura de artefatos, o vocabulário e as instruções dadas aos agentes. Ele não precisa acrescentar uma capacidade nova ao CLI.

Pense nele como uma camada de arquivos que o Spec Kit consulta. A escolha acontece arquivo por arquivo, não como uma substituição indivisível de todo o processo.

1. Preset, extensão ou override?

NecessidadeEscolha provávelExemplo
Mudar formato, linguagem ou regra de um processo existentePresetExigir uma seção de segurança em planos de implementação.
Adicionar comando, integração ou etapa novaExtensãoEnviar tarefas para Jira.
Fazer uma alteração pontual neste projetoOverride localAjustar somente o template de plano deste repositório.

Atalho mental: se o Spec Kit já sabe fazer o trabalho, mas a equipe quer que o agente o faça ou o descreva de outro jeito, investigue um preset.

2. Como o Spec Kit decide qual arquivo usar?

A precedência padrão vai do nível mais específico ao mais genérico:

1. Override do projeto: .specify/templates/overrides/
2. Presets instalados: prioridade menor vem primeiro
3. Extensões instaladas: prioridade menor vem primeiro
4. Templates do núcleo: .specify/templates/

Para cada nome de arquivo, a primeira camada que o fornece vence por padrão. Assim, um preset pode fornecer plan-template.md, enquanto outro fornece tasks-template.md; um arquivo ausente num preset continua sendo resolvido pela próxima camada.

Prioridade 5 vence prioridade 10. Um override local ainda vence ambos. Para verificar o resultado de verdade, use specify preset resolve <nome-do-arquivo>.

3. Substituir ou compor?

O padrão é replace: o arquivo do preset substitui por inteiro a versão de menor prioridade. Presets também podem declarar estratégia de composição para templates e comandos:

EstratégiaEfeitoUso típico
replaceUsa só o conteúdo do preset.Reformular completamente um artefato.
prependColoca o conteúdo do preset antes do conteúdo inferior.Adicionar uma orientação obrigatória no início.
appendColoca o conteúdo do preset depois do conteúdo inferior.Em um template, acrescentar uma seção; em um comando, anexar instruções finais.
wrapInsere o conteúdo inferior onde aparece {CORE_TEMPLATE}.Envolver um template ou comando com conteúdo próprio.

Sim: prepend, append e wrap valem tanto para templates quanto para comandos. Em ambos os casos, {CORE_TEMPLATE} marca onde o conteúdo de menor prioridade entra. Scripts são a exceção: aceitam replace e wrap (com o marcador $CORE_SCRIPT), mas não prepend nem append. Composição também pode encadear vários presets.

4. O exemplo pirata ensina mais do que o tom

O demo Pirate Speak aplicou um preset a um projeto Spring Boot 4. A ideia não era só renomear arquivos: os templates mudaram os artefatos gerados e os comandos ensinaram os agentes a preenchê-los com uma voz consistente.

O template muda o formato do artefato

Compare alguns títulos do template padrão com o spec-template.md do preset:

Template padrãoTemplate do presetO que muda
Feature SpecificationVoyage ManifestO documento passa a ser apresentado como o manifesto da viagem.
User Scenarios & TestingCrew Tales & Sea TrialsHistórias e testes ganham novos nomes, mantendo prioridades e cenários testáveis.
RequirementsDemands o' the VoyageOs requisitos continuam no artefato, mas sob a estrutura e o vocabulário do preset.

O template também troca o título do plano para Battle Plan e organiza tarefas como Crew Assignments. As saídas ainda cumprem funções reconhecíveis de spec, plan e tasks; mudam os rótulos, as seções e as instruções de preenchimento.

O comando muda como o agente trabalha

O arquivo commands/speckit.specify.md complementa o template. Ele instrui o agente a escrever todo o conteúdo em fala pirata, não apenas a copiar títulos temáticos. Também define como interpretar o pedido, limitar dúvidas importantes e revisar a spec antes de concluir.

Pedido: "Create a minimal Spring Boot MVC application"

Com o preset:
- o template fornece "Voyage Manifest" e "Crew Tales";
- o comando orienta o agente a preencher essas seções em fala pirata;
- o resultado do demo descreve três entregas priorizadas:
  página Thymeleaf, health check Actuator e API JSON de saudação.

O comando continua ligado ao fluxo técnico de specify: mantém scripts e encaminhamentos para etapas como clarify e plan. O preset altera as instruções e o material usado pelo agente; não precisa reimplementar a ferramenta de inicialização da feature.

Da demonstração à regra de uma equipe

Imagine trocar pirata por uma convenção de engenharia: o template de plano ganha uma seção Security Review, enquanto o comando speckit.plan instrui o agente a registrar ameaças relevantes e justificar quando a seção não se aplica. Assim, a estrutura pede a informação e o comando orienta como produzi-la.

No demo, os arquivos temáticos substituem os equivalentes padrão. Uma equipe poderia fazer uma mudança menor com append para adicionar uma seção ao template ou ao comando existente. Se a revisão precisar chamar um scanner externo, abrir um ticket ou acrescentar uma etapa executável, isso já pede uma extensão.

5. Experimente sem adivinhar

O projeto precisa estar inicializado com specify init. O fluxo de exploração e verificação é:

specify preset search
specify preset info <preset-id>
specify preset add <preset-id>
specify preset list
specify preset resolve plan-template.md

Antes de instalar, confira os arquivos e as instruções do pacote: presets da comunidade são mantidos por seus autores, não auditados ou endossados pelos mantenedores do Spec Kit. Para pausar o efeito, specify preset disable <preset-id>; para removê-lo, specify preset remove <preset-id>.

6. Pratique: diagnostique a precedência

O time instala um preset de segurança com prioridade 5 e outro de estilo com prioridade 10. Ambos fornecem plan-template.md. O projeto também tem um override local desse mesmo arquivo. Qual conteúdo será resolvido? Antes de revelar, responda de memória.

O override local. Ele está acima de todos os presets. Se for removido, o preset de segurança vence para esse arquivo, pois prioridade 5 vem antes de 10. Os demais arquivos ainda podem vir de camadas diferentes; confirme cada um com specify preset resolve.
