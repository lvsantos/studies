Autenticação no Spec Kit não é login no Copilot

Vitória de hoje: reconhecer quando o Specify CLI precisa de credenciais para buscar recursos remotos e separar isso da integração com seu agente.

Em uma frase

A autenticação do Spec Kit autoriza requisições HTTP de saída do Specify CLI para fontes remotas. Ela é opcional: sem configuração, as requisições são feitas sem credenciais.

Que problema resolve?

Um catálogo, uma extensão ou um artefato de release pode estar em um repositório privado ou exigir credenciais. Sem autenticação, o CLI não consegue ler esse conteúdo; com ela, consegue enviar a credencial apropriada ao host autorizado.

  • Buscar catálogos que exigem acesso autenticado;
  • baixar extensões privadas;
  • consultar ou baixar releases protegidas.

Isso não autentica o GitHub Copilot, não configura specify init --integration, não faz login no Git e não autentica usuários da aplicação que você está construindo. São credenciais para as requisições de rede do próprio CLI.

Quando usar

Configure autenticação quando você precisa acessar uma fonte remota privada ou protegida. Para recursos públicos que o CLI já consegue buscar anonimamente, em geral não é necessário configurar nada.

O arquivo de configuração fica em ~/.specify/auth.json. Exemplo para GitHub:

{
  "providers": [
    {
      "hosts": ["github.com", "api.github.com", "raw.githubusercontent.com", "codeload.github.com"],
      "provider": "github",
      "auth": "bearer",
      "token_env": "GH_TOKEN"
    }
  ]
}

O token fica numa variável de ambiente, não no JSON. Forneça GH_TOKEN por um gerenciador de segredos ou pelo ambiente seguro da sua sessão; limite as permissões ao acesso necessário. Restrinja o arquivo:

chmod 600 ~/.specify/auth.json

O modelo mental

Specify faz uma requisição HTTP
        ↓
O host corresponde a uma entrada em auth.json?
        ↓ sim
O CLI busca a credencial configurada e autentica a requisição

O host precisa corresponder à lista configurada. Se um download redirecionar para um host fora dela, o cabeçalho de autorização é removido para não vazar a credencial.

Pratique: diagnóstico de 403

Uma extensão privada do GitHub retorna 403. Antes de trocar a integração do agente, revele o primeiro diagnóstico útil:

Confira se o host acessado está em hosts, se a variável indicada em token_env está disponível e se o token tem permissão de leitura para o repositório. Se algum download usa raw.githubusercontent.com ou codeload.github.com, esses hosts também precisam estar listados.
