Lean: mantenha o fluxo, tire a cerimônia

Vitória de hoje: instalar e avaliar um fluxo specify → plan → tasks → implement que pede ao agente artefatos focados, sem as estruturas longas dos templates completos.

O problema que resolve

O fluxo estruturado do Spec Kit ajuda a orientar decisões, mas os templates completos podem trazer seções e boilerplate demais para um projeto pequeno ou para uma equipe que prefere documentos concisos. lean reduz esse atrito sem abandonar a sequência de artefatos.

1. O que muda (e o que não muda)

O preset fornece cinco comandos: speckit.specify, speckit.plan, speckit.tasks, speckit.implement e speckit.constitution. Cada comando é um prompt próprio, que cria ou atualiza diretamente o Markdown ou executa as tarefas. O manifest não fornece templates separados: as instruções do comando carregam a estrutura concisa.

ComandoResultadoIntenção do modo lean
specifyspec.mdDescrição enxuta do comportamento pedido.
planplan.mdAbordagem de implementação derivada da spec.
taskstasks.mdTarefas ordenadas por dependência a partir de spec e plano.
implementCódigo e progresso das tarefasExecutar tarefas em ordem e marcar andamento.
constitutionconstitution.mdCriar ou atualizar os princípios do projeto.

Os comandos substituem os equivalentes centrais; não se mesclam automaticamente com o texto original. Outros comandos que o preset não fornece, como clarify, continuam na resolução normal do projeto.

2. Ativar, inspecionar, experimentar

lean é um preset first-party bundled. O projeto precisa ter sido inicializado antes:

specify preset add lean
specify preset list
specify preset resolve speckit.specify
specify preset resolve speckit.plan

Os comandos do preset são registrados na integração de agente ativa. Faça uma feature pequena em uma branch de teste e compare os artefatos com uma execução anterior: a pergunta não é só se ficaram menores, mas se ainda contêm informação suficiente para construir e revisar a feature.

  1. Use /speckit.specify para descrever uma mudança observável.
  2. Use /speckit.plan e /speckit.tasks.
  3. Procure decisões, critérios de aceitação e dependências que tenham ficado implícitos.
  4. Execute /speckit.implement só depois de validar que o plano e as tarefas estão claros.

3. O compromisso por trás da concisão

Lean troca scaffolding extenso por instruções mais diretas. Isso reduz campos para preencher, mas também reduz os lembretes estruturais que ajudam a não esquecer análises. Não interprete “lean” como “sem requisitos” ou “sem revisão”: critérios verificáveis e decisões técnicas ainda precisam estar escritos quando o projeto depende deles.

Se um time precisa de uma seção obrigatória de segurança, compatibilidade ou migração, o modo lean pode não a pedir por padrão. Pode-se criar uma convenção própria com override ou preset; se a necessidade for um comando/integração novo, investigue uma extensão. Veja a distinção entre preset, override e extensão.

4. Retornar ao fluxo anterior

Para comparar sem desinstalar, desative temporariamente. Lembre que os comandos já registrados continuam disponíveis no agente; para remover a alteração por completo, remova o preset:

specify preset disable lean
specify preset enable lean
specify preset remove lean

Depois da remoção, confira specify preset resolve speckit.specify e revise arquivos de comando registrados na integração. Não faça a comparação só pelo tamanho: confira a qualidade dos artefatos e a facilidade de revisar o diff.

5. Pratique: menos texto ou menos controle?

Um time instalou lean e notou que o plano ficou curto. Qual evidência indica que o preset está ajudando, em vez de apenas esconder decisões?

O plano continua explícito o bastante para orientar tarefas e revisão. Confira abordagem, dependências e decisões necessárias ao projeto; se algum controle obrigatório sumiu, adicione-o à convenção antes de implementar.
