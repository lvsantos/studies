Coding Agent Context: manter o agente no contexto certo

Vitória de hoje: entender como a extensão oficial agent-context sincroniza o contexto do agente sem misturar esse trabalho com a investigação de bugs ou a avaliação de ideias.

O mapa mental

Bug Fix investiga e corrige um defeito. Idea Assessment decide se uma ideia merece investimento. Coding Agent Context mantém no arquivo do agente as instruções e referências necessárias para executar o trabalho com continuidade.

Ela é uma extensão oficial, bundled e opt-in. O Spec Kit não altera o arquivo de contexto por conta própria: essa responsabilidade começa quando você instala a extensão.

1. Que problema ela resolve?

Agentes de programação dependem de um arquivo de contexto, como AGENTS.md, CLAUDE.md, GEMINI.md ou .github/copilot-instructions.md. Se esse arquivo não acompanha o plano ativo do projeto, cada conversa pode começar com instruções incompletas ou desatualizadas.

A extensão resolve essa lacuna mantendo uma seção gerenciada no arquivo de contexto. Ela atualiza as referências do Spec Kit sem sobrescrever o conteúdo que a equipe mantém fora dessa seção.

2. Como instalar

specify extension add agent-context

A instalação deve ser feita na raiz de um projeto já inicializado com Spec Kit. Como é opt-in, não instalar a extensão é uma decisão válida: nesse caso, o arquivo de contexto permanece sob administração manual.

Para desativar os hooks sem remover a extensão:

specify extension disable agent-context
# Para reativar:
specify extension enable agent-context

3. Como usar

O comando principal atualiza a seção gerenciada do arquivo de contexto:

/speckit.agent-context.update

Em integrações que usam skills com hífens, a mesma operação aparece como:

/speckit-agent-context-update

Por padrão, a extensão delimita sua área com:

<!-- SPECKIT START -->
...
<!-- SPECKIT END -->

O conteúdo fora desses marcadores continua intacto. Isso permite que regras da organização e instruções específicas do agente coexistam com a parte atualizada pelo Spec Kit.

4. Exemplo real com GitHub Copilot

Imagine um projeto que usa somente o GitHub Copilot. Antes de instalar a extensão, o arquivo .github/copilot-instructions.md pode conter apenas as regras mantidas manualmente pela equipe:

# Instruções do projeto

- Use TypeScript.
- Escreva testes para novas funcionalidades.
- Não altere o banco sem criar uma migração.

Depois de instalar a extensão e executar:

specify extension add agent-context
/speckit-agent-context-update

o arquivo pode passar a ter uma seção gerenciada pelo Spec Kit:

# Instruções do projeto

- Use TypeScript.
- Escreva testes para novas funcionalidades.
- Não altere o banco sem criar uma migração.

<!-- SPECKIT START -->
## Spec Kit

A feature ativa possui os seguintes artefatos:

- Spec: `specs/001-checkout/spec.md`
- Plano: `specs/001-checkout/plan.md`
- Tarefas: `specs/001-checkout/tasks.md`

Consulte esses arquivos antes de implementar.
<!-- SPECKIT END -->

Se o plano mudar depois de /speckit-plan, a extensão atualiza apenas o trecho entre os marcadores. As regras manuais continuam intactas. Portanto, mesmo com um único agente, a extensão pode evitar que o Copilot trabalhe com uma referência antiga do plano ativo.

5. O que ela atualiza?

A extensão pode manter a referência ao plano ativo e sincronizar mais de um arquivo de contexto quando o projeto realmente usa vários agentes. A configuração fica em:

.specify/extensions/agent-context/agent-context-config.yml

Nela, você pode ajustar os arquivos monitorados e os marcadores. Para arquivos .mdc, a extensão também garante que o frontmatter contenha alwaysApply: true.

Os hooks declarados pela extensão executam a atualização depois de etapas como specify e plan. Ainda assim, a atualização sob demanda continua disponível quando o contexto mudou e você quer sincronizá-lo imediatamente.

6. Como ela se relaciona com Bug Fix e Assess?

ExtensãoPergunta respondidaResultado principal
bugO que quebrou e como provar a correção?assessment, fix e test
assessEsta ideia merece investimento?research, concept e decision
agent-contextQue instruções o agente deve carregar?seção sincronizada no contexto

Portanto, ela não substitui nenhuma das duas aulas anteriores. Ela melhora a continuidade do agente enquanto qualquer um desses fluxos está sendo executado.

7. Quando usar

  • o projeto tem regras importantes que o agente precisa receber em toda sessão;
  • o plano ativo deve aparecer no arquivo de contexto;
  • mais de uma integração de agente compartilha instruções;
  • a equipe quer automação sem perder controle sobre o texto manual do arquivo.

Não use a extensão apenas para evitar uma edição manual ocasional. O ganho aparece quando contexto e plano mudam com frequência ou quando vários agentes precisam permanecer alinhados.

8. Prática: qual extensão escolher?

Uma ideia já recebeu go no Idea Assessment. Agora o time quer executar o plano com Copilot e Claude, mantendo as mesmas regras do projeto e a referência do plano ativo. Qual extensão resolve o problema?

Use agent-context. O resultado de assess decide o investimento; a extensão de contexto garante que os agentes recebam as instruções e referências necessárias durante a execução.
