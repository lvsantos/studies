Converge: verificar se a implementação chegou ao destino

Vitória de hoje: comparar código, especificação, plano e tarefas, transformando lacunas reais em trabalho rastreável.

A ideia central

Implement constrói; Converge confere. O comando avalia o estado atual do código contra a intenção registrada em spec.md, as decisões de plan.md e o trabalho descrito em tasks.md.

Ele não é uma inspeção de diferenças do Git. É uma verificação de completude baseada nos artefatos da feature.

1. O que o comando faz

No GitHub Copilot, use a skill com hífens:

/speckit-converge

A documentação também mostra /speckit.converge. A forma depende do agente; a etapa é a mesma.

Antes de avaliar, o comando precisa encontrar uma especificação, um plano e uma lista de tarefas completos. Ele deve ser executado depois de implement, não no lugar de tasks ou implement.

2. O que é comparado

FontePergunta
spec.mdOs requisitos e cenários de aceitação foram atendidos?
plan.mdAs decisões técnicas e os pontos de integração foram respeitados?
tasks.mdAs tarefas estão concluídas e a implementação cobre o trabalho previsto?
Código atualO comportamento construído corresponde aos artefatos?

O comando também considera a Constitution como restrição de governança. Uma implementação que cumpre a funcionalidade, mas viola um princípio obrigatório, ainda tem uma lacuna.

3. Dois resultados possíveis

Converged

Se nada faltar, o comando informa que a implementação satisfaz os artefatos e deixa tasks.md byte a byte inalterado. A feature está pronta para a revisão final do time.

Tasks appended

Se encontrar uma lacuna, o comando acrescenta uma seção Convergence ao final de tasks.md. Cada item recebe um ID novo e uma referência à origem do trabalho pendente.

## Phase 6: Convergence

- [ ] T042 Adicionar teste do cenário de exportação por usuário (US1/AC2) (missing)

O Converge não implementa essa tarefa e não altera os outros artefatos. Depois, execute /speckit-implement novamente e rode /speckit-converge até não restarem lacunas.

4. O que Converge não faz

  • não modifica spec.md ou plan.md;
  • não corrige o código encontrado;
  • não apaga ou renumera tarefas existentes;
  • não usa o histórico do Git como fonte de intenção;
  • não deve ser executado antes de existir um tasks.md completo e uma implementação.

Se o problema encontrado for uma especificação ambígua ou uma decisão técnica errada, a tarefa de convergência pode indicar a lacuna, mas a correção deve voltar ao artefato que possui a decisão.

5. Pratique: qual é o próximo passo?

O Converge encontrou duas tarefas pendentes e as anexou a tasks.md. O que fazer agora?

Executar /speckit-implement novamente para realizar as tarefas anexadas e depois rodar /speckit-converge outra vez. O ciclo termina quando o resultado for Converged.
