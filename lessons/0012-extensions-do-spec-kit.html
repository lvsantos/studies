Extensions: adicionar capacidades ao Spec Kit

Vitória de hoje: instalar, inspecionar, configurar e governar uma extensão sem confundi-la com um preset ou com o núcleo do Spec Kit.

O mapa mental

Uma extensão amplia o que o Spec Kit consegue fazer. Ela pode adicionar comandos, templates, scripts, hooks, fases de processo ou integrações externas.

Preset muda como uma capacidade existente funciona; extension adiciona uma capacidade ou integração. Essa é a distinção que orienta todo o diagnóstico.

1. O ciclo de vida de uma extensão

As extensões exigem um projeto já inicializado com specify init. O ciclo básico é:

  1. Descobrir: procurar no catálogo usando tags, autor ou status de verificação.
  2. Inspecionar: consultar descrição, versão, comandos, configuração e origem.
  3. Instalar: adicionar a extensão ao projeto e registrar seus comandos na integração ativa.
  4. Configurar: copiar o template de configuração e ajustar as opções necessárias.
  5. Verificar: listar a extensão, testar o comando e confirmar os efeitos nos arquivos.
  6. Atualizar ou remover: manter a versão ou retirar a extensão quando ela deixar de ser necessária.
specify extension search
specify extension info <name>
specify extension add <name>
specify extension list
specify extension update <name>
specify extension remove <name>

2. De onde a extensão vem?

O Spec Kit separa descoberta de instalação por uma razão de segurança:

FonteUsoConfiança
defaultCatálogo oficial e instalável.Fonte de instalação aprovada pelo projeto.
communityDescobrir extensões disponíveis.Discovery-only: não é instalável automaticamente.
catálogo próprioDistribuir extensões aprovadas pela organização.Instalável apenas quando a equipe o mantém e avalia.
URL diretaInstalar um arquivo ou release específico.Exige revisar a origem antes de usar.

Para inspecionar os catálogos:

specify extension catalog list
specify extension info <name>
specify extension add <name> --from <archive-url>

Um catálogo público de comunidade é uma superfície de descoberta, não uma autorização para executar código de terceiros sem revisão.

3. O que uma extensão instala

Uma extensão pode entregar componentes diferentes:

  • Commands: novas skills ou comandos para o agente;
  • Templates: novos artefatos ou alterações específicas de um domínio;
  • Scripts: automações auxiliares executadas pelo processo;
  • Hooks: ações oferecidas antes ou depois de comandos;
  • Integrações: conexão com ferramentas como Git, Jira ou sistemas internos.

O comando JSON ajuda a enxergar essa composição:

specify extension list --json

Além de nome, versão, autor e origem, o resultado informa quantos comandos, templates, scripts e hooks a extensão fornece.

4. Configuração em camadas

Extensões normalmente guardam sua configuração em .specify/extensions/<ext>/:

.specify/extensions/<ext>/
├── <ext>-config.template.yml
├── <ext>-config.yml
└── <ext>-config.local.yml

A configuração é combinada nesta ordem, da base para a maior precedência:

  1. defaults definidos pela extensão;
  2. configuração do projeto, versionada;
  3. override local, normalmente ignorado pelo Git;
  4. variáveis de ambiente SPECKIT_<EXT>_*.

Para começar, copie o template fornecido pela própria extensão:

cp .specify/extensions/<ext>/<ext>-config.template.yml \
   .specify/extensions/<ext>/<ext>-config.yml

A configuração compartilhável fica no arquivo do projeto; segredos, caminhos pessoais e ajustes de máquina ficam no override local ou em variáveis de ambiente.

5. Hooks: pontos de extensão do processo

Hooks conectam uma extensão a eventos como before_implement, after_implement, before_tasks ou after_tasks. Eles podem ser opcionais ou automáticos:

  • Hook opcional: o agente apresenta a ação e permite que o usuário decida se quer executá-la.
  • Hook obrigatório: o processo o apresenta como uma etapa automática que precisa ser executada.

O registro do projeto fica em .specify/extensions.yml. Um hook deve explicar seu comando, extensão, prioridade, condição e efeito. Quanto mais forte o efeito, maior a necessidade de revisão antes de habilitá-lo.

6. Administrar sem perder o controle

AçãoComandoCuidados
Desabilitarspecify extension disable <name>Remove os comandos da disponibilidade sem apagar a instalação.
Habilitarspecify extension enable <name>Reativa os comandos instalados.
Priorizarspecify extension set-priority <name> <N>Menor número vence quando extensões oferecem o mesmo comando.
Removerspecify extension remove <name>Configurações são preservadas em backup por padrão.

Depois de instalar ou habilitar uma extensão, o agente pode precisar ser reiniciado para carregar os novos comandos.

7. Pratique: extensão ou preset?

O time quer adicionar um comando que envia os resultados de converge para Jira. Também quer que todo plan.md tenha uma seção de risco. Qual escolha faz sentido?

Extensão para a integração com Jira; preset para a seção obrigatória de risco. A primeira adiciona uma capacidade externa. A segunda altera o formato esperado de um artefato existente.
