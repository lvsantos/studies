O MCP do Spec Kit ainda é uma ponte pequena

Vitória de hoje: entender como um host MCP inicia o Specify CLI, quais ferramentas estão disponíveis e por que isso ainda não equivale a operar o Spec Kit pelo agente.

Primeiro, o limite

specify mcp é experimental e, nesta versão, só permite consultar a versão do CLI. A interface e o inventário podem mudar antes de serem declarados estáveis.

1. O que o comando inicia?

specify mcp

Ele inicia um servidor MCP local usando stdio: o host MCP executa o comando como subprocesso e troca mensagens pelo processo. Não há transporte HTTP ou SSE, serviço em background, nem seleção de transporte. O CLI também não escreve banner, logs ou mensagens de inicialização em stdout, pois esse canal carrega o protocolo.

Portanto, o comando não é um servidor web para publicar na rede. É o host MCP, configurado à parte, que precisa saber iniciar specify mcp. A referência oficial não prescreve um arquivo de configuração universal: o formato depende do host.

2. Três ferramentas, um comando permitido

Ferramenta MCPFunçãoEstado atual
specify_list_commandsLista comandos suportados via MCP.O inventário inclui version.
specify_describe_commandDescreve um comando pontuado suportado.Pode descrever version.
specify_run_commandExecuta um comando suportado pelo Specify CLI.Só aceita version; os demais retornam unavailable_command.

Na prática, a chamada de execução equivale a specify version --json, feita em um processo filho isolado que usa o mesmo ambiente Python do CLI ativo.

3. Interpretar o resultado

Quando funciona, o resultado é o objeto JSON direto da saída do CLI, com cli_version, runtime, system e features. Não espere um envelope genérico com campos schema_version, ok ou result.

Se o CLI falhar, a ferramenta retorna um erro MCP com error.code, error.message e error.details, extraído do erro JSON estruturado em stderr. Se a saída do processo estiver vazia, misturada, malformada ou não for JSON, o adaptador sinaliza adapter_internal_error sanitizado, sem inventar sucesso nem expor traceback.

4. O que ainda não está exposto?

  • Descoberta de projetos ou leitura de specs, planos e tarefas;
  • criação ou mutação de artefatos;
  • instalação, atualização ou remoção de integrações e componentes;
  • execução de workflows, confirmações ou níveis de acesso.

Isso evita uma conclusão tentadora, mas incorreta: ter um MCP server não significa que o agente já possa executar os comandos centrais do fluxo. Também não substitui specify init --integration ...; são superfícies diferentes.

Pratique: o agente pode criar uma spec?

Você configurou o host para iniciar specify mcp. Pode pedir ao agente que crie uma spec com specify_run_command?

Não, pela interface MCP documentada atualmente. O único comando da CLI disponível é version, que consulta dados de versão e ambiente. Criar uma spec exigiria uma capacidade que ainda não está exposta nesse servidor.
