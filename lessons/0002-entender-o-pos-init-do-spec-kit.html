O que nasceu depois do specify init?

Vitória de hoje: olhar para .github/skills e .specify e saber qual peça usar em cada etapa do desenvolvimento.

O mapa mental

.github/skills é a superfície que o GitHub Copilot lê para oferecer os comandos do método. .specify é o kit de suporte: templates, memória do projeto, workflows e metadados da integração.

Em uma frase: skills dizem ao agente como agir; .specify organiza o processo e seus artefatos.

1. Reconheça as duas pastas

PastaO que guardaVocê mexe quando...
.github/skills/Uma pasta por comando, cada uma com SKILL.md.Quer entender ou personalizar o comportamento de uma etapa.
.specify/Templates, constituição, scripts, workflows e configuração.Quer configurar o método, criar artefatos ou diagnosticar o fluxo.

No seu projeto, .specify/integration.json confirma a integração com Copilot, e .specify/workflows/workflow-registry.json registra o ciclo instalado.

2. Siga o ciclo, uma decisão por vez

  1. Constitution: define princípios e limites do projeto em .specify/memory/constitution.md. Faça primeiro quando o projeto ainda não tem regras compartilhadas.
  2. Specify: transforma uma ideia em spec.md: usuários, cenários, requisitos testáveis e critérios de sucesso.
  3. Clarify: resolve ambiguidades importantes e devolve as respostas para a especificação.
  4. Plan: transforma a especificação em uma decisão técnica documentada, incluindo pesquisa, modelo de dados e guia rápido.
  5. Checklist: cria ou usa uma lista de revisão para encontrar lacunas antes de construir.
  6. Tasks: quebra o plano em tarefas executáveis, ordenadas por dependência.
  7. Analyze: compara especificação, plano e tarefas para encontrar contradições antes da implementação.
  8. Implement: executa tasks.md, valida o resultado e marca as tarefas concluídas.
  9. Converge: verifica o código contra os artefatos e acrescenta tarefas para qualquer parte ainda não construída.

Nem todo ajuste precisa de todos os portões. Para uma feature de produção, o caminho completo é o mais seguro; para explorar uma ideia, comece por specify e avance conforme o risco.

3. Pratique: escolha a próxima peça

Você recebeu uma ideia vaga: “quero permitir que usuários exportem seus estudos”. A especificação ainda não existe. Qual comando vem primeiro?

/speckit-specify. Primeiro transforme a intenção em cenários, requisitos e critérios de sucesso. plan só faz sentido depois que existe algo suficientemente claro para planejar.

4. Verifique no próprio projeto

find .github/skills -name SKILL.md | sort
find .specify -maxdepth 2 -type f | sort
cat .specify/integration.json
cat .specify/workflows/workflow-registry.json

O resultado esperado é uma coleção de skills em .github/skills e, dentro de .specify, arquivos como templates/, memory/, scripts/, workflows/ e os arquivos de integração.
