Do pedido à feature: os comandos centrais do Spec Kit

Vitória de hoje: olhar para uma ideia e saber qual comando usar agora, qual artefato ele produz e como o Git protege o caminho até a implementação.

O mapa mental

O Spec Kit separa decisões que costumam ser misturadas: primeiro o que construir, depois como construir, depois em que ordem executar. A forma do comando muda conforme o agente: no GitHub Copilot deste projeto, use /speckit-specify; em documentações que usam slash commands com pontos, a mesma etapa aparece como /speckit.specify.

1. O exemplo: exportar estudos

Imagine uma necessidade real: usuários querem exportar seus estudos para consultar o conteúdo fora da aplicação. Não comece pedindo código. Comece transformando a intenção em um acordo verificável.

/speckit-specify Permitir que usuários exportem seus estudos em um formato legível, preservando título, conteúdo e data de atualização.

O resultado esperado é uma pasta em specs/ com uma spec.md. Ela deve explicar usuários, cenários, requisitos e critérios de sucesso. O comando specify responde: o que e por que estamos construindo?

2. A sequência principal

ComandoPergunta que respondeResultado
constitutionQuais princípios governam o projeto?Regras compartilhadas em constitution.md; normalmente uma vez por projeto.
specifyO que precisa ser construído e para quem?spec.md com necessidade, cenários e requisitos.
clarifyO que ainda pode ser interpretado de mais de uma forma?Respostas incorporadas à spec; use antes de planejar quando houver ambiguidade.
planComo construiremos isso?plan.md com stack, arquitetura e decisões técnicas.
checklistA especificação está completa e clara?Checklist de qualidade dos requisitos, revisado por uma pessoa.
tasksQual é a ordem executável do trabalho?tasks.md com tarefas ordenadas por dependência.
analyzeSpec, plano e tarefas ainda concordam?Análise somente leitura de conflitos, lacunas e cobertura.
implementComo transformar tarefas em código?Execução das tarefas, testes e atualização do estado de execução.
convergeFalta alguma coisa para a implementação realmente cumprir a intenção?Lacunas viram novas tarefas; repita implement/converge até convergir.

3. Um passeio completo

Para uma feature de produção, o fluxo completo fica assim:

/speckit-constitution
/speckit-specify "Permitir exportação de estudos"
/speckit-clarify
/speckit-plan "Use a stack já existente no projeto"
/speckit-checklist
/speckit-tasks
/speckit-analyze
/speckit-implement
/speckit-converge

Há também um caminho curto para uma mudança pequena: specify → plan → tasks → implement → converge. A escolha não é ritual: quanto maior o risco de mal-entendido, mais valiosos são clarify, checklist e analyze.

Curiosidade: e o Git?

A extensão de Git é opcional e entra como um complemento ao fluxo central. Para adicioná-la ao projeto, instale-a pelo CLI:

specify extension add git

Depois disso, ela pode criar branches numerados, como 001-exportar-estudos, para organizar cada feature. O benefício não é “automatizar Git” por si só, mas dar uma fronteira visível para cada mudança:

  • isolamento: código e artefatos não se misturam com outra feature em andamento;
  • revisão: um pull request pode examinar spec, plano, tarefas e código como uma unidade;
  • rastreabilidade: commits e branch ajudam a ligar intenção, decisão técnica e implementação;
  • reversibilidade: fica mais simples comparar, pausar ou desfazer uma tentativa.

A extensão não é necessária para o Spec Kit localizar a feature: por padrão, o projeto mantém essa referência em .specify/feature.json. Branch e feature ativa são conceitos relacionados, não idênticos; trocar de branch com git checkout não necessariamente troca a pasta que os comandos usarão.

4. Pratique: escolha o próximo comando

A spec de exportação existe, mas “arquivo legível” pode significar PDF, Markdown ou texto simples. Qual comando vem antes do plano?

/speckit-clarify. A decisão sobre formato altera requisitos e critérios de sucesso. Planejar antes de resolver essa ambiguidade faria o plano parecer preciso, mas construiria sobre uma escolha escondida.
