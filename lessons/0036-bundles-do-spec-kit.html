Bundles: provisionar um setup completo por papel

Vitória de hoje: decidir quando instalar um bundle e explicar o que ele reúne sem confundi-lo com uma extensão, preset ou workflow.

A ideia central

Um bundle é um manifesto versionado que reúne componentes existentes do Spec Kit: extensões, presets, workflows e etapas de workflow. Ele instala o conjunto como uma unidade; não cria um novo motor nem substitui o comportamento próprio de cada componente.

O benefício aparece quando uma equipe ou papel precisa receber repetidamente o mesmo setup, com versões e dependências declaradas. Para uma única necessidade isolada, instalar só a peça necessária costuma ser mais simples.

1. O que cada peça faz?

As três primeiras peças respondem ao que o Spec Kit faz e como o faz. O bundle responde a outra pergunta: quais componentes este papel ou equipe deve receber juntos? Um bundle pode incluir uma extensão Git, mas a aula sobre Git descreve a capacidade; não significa que ela esteja incluída em todo bundle de desenvolvimento.

3. Benefícios e limites

  • Setup repetível: novas pessoas ou projetos recebem o mesmo conjunto declarado.
  • Versões visíveis: o manifesto fixa as versões dos componentes para uma instalação reproduzível.
  • Menos coordenação manual: não é preciso descobrir e instalar cada dependência uma a uma.
  • Rastreio e manutenção: o Spec Kit registra quais componentes cada bundle trouxe para atualização e remoção controladas.

Bundle não garante que a combinação seja adequada, segura ou compatível com qualquer projeto. info mostra os componentes resolvidos antes da instalação; ainda é preciso revisar suas origens, requisitos e efeitos. A instalação não troca uma integração já ativa para satisfazer um bundle incompatível.

Remover um bundle remove os componentes que ele forneceu, preservando o que outro bundle ainda usa. Componentes instalados independentemente não são adotados pelo bundle. Catálogos comunitários podem ser apenas para descoberta, e componentes referenciados ainda precisam ser resolvidos pelas fontes configuradas.

4. Quando usar?

SituaçãoEscolha
Um novo time precisa do mesmo conjunto coordenado de extensões, presets e workflows.Bundle
Quero somente branches Git para uma feature.Extension
Quero adicionar uma regra de segurança ao formato do plano.Preset ou override local

Regra prática: escolha bundle para padronizar um setup completo que deve ser distribuído e mantido como conjunto. Se ainda está experimentando, ou precisa de apenas uma capacidade, comece pela peça individual e componha o bundle depois que as dependências e o valor do setup estiverem claros.

5. Inspecione antes de instalar

Busque e leia o plano expandido do bundle antes de aplicar suas mudanças:

specify bundle search bug
specify bundle info bugfix
specify bundle install bugfix
specify bundle list
specify bundle update bugfix

info pode ser usado fora de um projeto e mostra componentes, versões fixadas e indicador de confiança. install pode inicializar um projeto ainda não preparado. Antes de instalar um bundle de origem desconhecida, confira também os catálogos dos componentes que ele referencia; prefira uma origem confiável e examine cada componente.

6. Pratique: peça ou pacote?

Uma equipe quer padronizar a entrada de novos projetos. Cada setup precisa de uma extensão, um preset e um workflow específicos, nas versões acordadas, e deve poder ser instalado e atualizado como conjunto. Qual bloco resolve melhor essa necessidade?
