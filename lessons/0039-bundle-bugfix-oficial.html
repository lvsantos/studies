bugfix: diagnóstico, gate, reparo e prova

Vitória de hoje: identificar o conjunto que o bundle fornece e separar “workflow concluído” de “bug verificado”.

Quando usar

Use este bundle quando há comportamento existente quebrado e você quer uma sequência governada para investigar antes de alterar código. Ele é first-party e verificado no catálogo oficial. Para decidir se uma ideia nova merece investimento, use assess, não bugfix.

1. O que ele instala

ComponenteVersão declaradaResponsabilidade
Extension bug1.0.0Comandos speckit.bug.assess, fix e test.
Workflow bugfix1.0.0Orquestra diagnóstico, revisão humana, correção e verificação.

O manifesto fixa as duas versões e requer Spec Kit >=0.9.0; não inclui preset nem step independente. A extensão fornece as operações; o workflow decide ordem e ponto de aprovação. Esse empacotamento não muda a lógica descrita na lição 14 nem o fluxo da lição 32.

2. O workflow por dentro

  1. assess: investiga o relato, propõe causa e remediação; não altera código-fonte.
  2. review-assessment: gate humano. approve permite avançar; reject aborta antes do patch.
  3. fix: aplica a remediação e registra mudanças. É a etapa que altera código.
  4. test: roda a reprodução/testes relevantes e registra evidências.

Os relatórios são gravados em .specify/bugs/<slug>/: assessment.md, fix.md e test.md. Mantenha o mesmo slug nas entradas. A extensão e seu workflow funcionam juntos como os itens das lições de extensão e workflow, respectivamente.

O status do run mede execução das etapas; o relatório de teste mede evidência sobre o bug. Um run completed com resultado partial não prova a correção. Os resultados de domínio são verified, partial e failed.

3. Inspecione e execute

specify bundle info bugfix
specify bundle install bugfix
specify bundle list

Após inspecionar o plano expandido e instalar o bundle, forneça o relato e um slug:

specify workflow run bugfix \
  --input report="Login com senha vazia termina em erro 500" \
  --input slug=login-empty-password

O instalador resolve cada componente pela sua origem e rotina próprias, mantém registro de quais itens o bundle forneceu e recusa conflitos de integração. A remoção preserva componentes ainda necessários a outro bundle e não remove componentes independentes. Na instalação por ID do catálogo first-party, o manifesto é buscado online; inspecione os componentes antes de rodar o processo.

4. Pratique: run completo, bug resolvido?

O run terminou em completed, mas test.md diz partial: a reprodução original não pôde ser executada. O que foi comprovado?
