Atualizar o Spec Kit sem misturar as camadas

Vitória de hoje: atualizar a CLI, os arquivos do projeto e os componentes customizados como operações separadas, prevendo onde pode haver incompatibilidade.

Modelo mental

Há duas atualizações diferentes: a ferramenta specify instalada na máquina e os arquivos/componentes instalados dentro de cada projeto. Atualizar uma não atualiza automaticamente tudo da outra.

1. Sequência para um projeto existente

  1. Confira a versão e simule: specify self check e specify self upgrade --dry-run.
  2. Faça commit ou backup das customizações; leia as notas da versão, sobretudo em um salto de versão principal.
  3. Atualize a CLI: specify self upgrade (ou fixe uma tag com --tag vX.Y.Z).
  4. Dentro do projeto, confira o estado com specify integration status e atualize cada integração instalada com specify integration upgrade <key>.
  5. Atualize extensões independentes com specify extension update. Atualize também presets, workflows e bundles pelos comandos próprios, conforme quem é dono de cada componente.
  6. Revise o diff, resolva avisos de arquivos modificados e rode comandos representativos do seu fluxo.

Use specify init --here --force como recuperação quando faltam manifestos/metadados, não como rotina: essa rota ampla não oferece a mesma checagem por integração antes de substituir arquivos. O guia oficial confirma que specs, planos, tarefas, código e histórico Git ficam fora da atualização normal por manifesto.

2. O que atualiza cada camada?

CamadaAtualizaçãoRisco típico
CLIspecify self upgradeComandos/recursos novos podem exigir atualizar também os arquivos do projeto.
Integração e núcleo do projetospecify integration upgrade <key>Alterações locais em arquivos gerenciados podem bloquear a atualização; não use --force sem revisar o diff.
Extensõesspecify extension updateComandos, templates e hooks podem mudar; confira requisitos de versão e comportamento.
Presetsspecify preset update <id>Atualiza comandos/templates do preset, não garante que suas suposições ainda correspondam ao núcleo novo.
Workflowsspecify workflow update [id]Um overlay pode deixar de encontrar um passo se o workflow-base renomear/remover seu ID âncora.
Bundlesspecify bundle update <id>Reaplica versões fixadas no bundle; componentes que ele possui devem ser atualizados por ele.

Extensões, presets, workflows e bundles podem evoluir independentemente do núcleo. Uma atualização pode quebrar compatibilidade se mudar um comando, template, hook, requisito, entrada ou passo usado pela customização. Restrições como requires.speckit_version ajudam quando declaradas, mas não substituem teste. A promessa de compatibilidade do Spec Kit na mesma versão principal não é garantia universal para pacotes de terceiros nem para customizações próprias.

3. Seu preset faz append em um comando

Imagine que o comando central termina com uma instrução e seu preset acrescenta outra ao final. O append compõe o texto do preset depois do texto-base resolvido; ele não “cola para sempre” a instrução em um arquivo de origem. Comandos são materializados para a integração ativa e recalculados durante instalação/atualização/reconciliação do preset.

Antes: núcleo v1 + sua instrução append
Depois: núcleo v2 + sua instrução append

Atualizar apenas a CLI não troca os arquivos de comando do projeto. Atualizar a integração atualiza a camada de comandos centrais; atualizar/reconciliar o preset recompõe os comandos gerenciados com a nova base. Porém, a frase acrescentada continua sendo sua responsabilidade: se o núcleo v2 mudou os nomes dos artefatos, a ordem das etapas ou a semântica do comando, a instrução anexada pode ficar redundante, contraditória ou inválida.

Procedimento para esse caso
  1. Atualize a CLI e os arquivos da integração.
  2. Inspecione o arquivo do preset e a origem efetiva com specify preset resolve <nome-do-comando>.
  3. Revise/atualize o preset e, se apropriado, rode specify preset update <id> para recompô-lo contra o núcleo novo.
  4. Abra o comando materializado na pasta da integração ativa; confirme que o núcleo novo e o trecho anexado aparecem uma única vez e na ordem esperada.
  5. Execute o comando em uma feature de teste e revise o artefato gerado.

Atenção: a atualização de preset é destrutiva: remove o preset instalado e depois tenta adicioná-lo de novo. Se a nova origem falhar, o preset anterior pode já ter sido removido. Confira a origem, faça backup/commit e use a saída de preset info/preset resolve antes.

Com replace, o preset substitui por inteiro o comando/template central: você pode não receber as melhorias do núcleo até atualizar o próprio preset. Com wrap, confira se o ponto {CORE_TEMPLATE} continua correto. Para templates, a resolução acontece em tempo de execução; para comandos, não: o agente usa o arquivo materializado.

4. Workflows, bundles e outras incompatibilidades

  • Workflows: atualizar um workflow pode preservar overlays locais, mas um overlay depende dos IDs dos passos do workflow-base. Rode specify workflow resolve <id> para ver a composição; depois valide e execute em um caso de teste.
  • Bundles: o bundle é o dono das versões dos componentes que instalou. bundle update reaplica os pins atualizados e pode remover componentes que saíram do manifesto. Componentes independentes não são adotados nem atualizados pelo bundle.
  • Extensões: algumas são empacotadas com o Spec Kit; podem exigir atualizar a CLI antes de atualizar a extensão. Se aparecer erro de incompatibilidade, confira o requisito declarado.

Em qualquer camada, leia os arquivos novos antes de forçar substituição. “A instalação terminou” prova que o pacote passou pela instalação, não que a política, o comando ou o workflow ainda produz o resultado pretendido.

Pratique: recupere a distinção

Sem olhar acima: se você atualizou a CLI e ainda não atualizou a integração do projeto, os comandos existentes já mudaram? E o que precisa acontecer para o seu append voltar a ser combinado com a base nova?

Não. A atualização da CLI não atualiza os arquivos do projeto. Atualize a integração e depois atualize/reconcilie o preset; então inspecione o comando materializado e teste se o texto acrescentado ainda faz sentido.
